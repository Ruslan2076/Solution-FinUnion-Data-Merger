## 3. Развёрнутая спецификация критичного потока

Поток F-01 выбран как критичный: на нём держится единый клиентский идентификатор, без которого не выполняется ни одно требование промежуточного состояния.

| Параметр спецификации | Значение |
|---|---|
| Источник → приёмник | FU CRM → Integration Layer (ESB, DQ Gateway) → MDM Customer Hub |
| Бизнес-сущность | E-01 клиент, E-13 согласие |
| Действие | [V] валидация на шине → [C] создание или [U] изменение золотой записи с дедупликацией |
| Паттерн интеграции | Асинхронный, событийный, публикация и подписка |
| Контракт и формат | JSON, версионированная JSON Schema в реестре схем, обратно совместимые изменения |
| Гарантии доставки | At-least-once, число повторов 3, очередь недоставленных сообщений для клиентского потока |
| SLA и мониторинг | Сквозная задержка менее 5 минут, оповещение при отставании потребителя выше порога и при росте очереди недоставленных |
| Безопасность | Шифрование канала, ПДн не пишутся в технические логи шины, доступ к топику по ролевой модели, журналирование обращений |
| Правило разрешения конфликтов | Неоднозначно сопоставленные пары не сливаются автоматически, а изолируются в карантине |
| Data Owner и Data Steward | Розничный бизнес и МСБ совместно как владельцы, Data Office как стюард клиентских данных |
| Критерий отключения переходного механизма | Перевод CRM RetailBank на единую CRM FinUnion, после чего поток F-02 прекращается |

Спецификация читается тремя разными командами: разработчик видит задание на асинхронного потребителя с валидацией по схеме, служба эксплуатации — настройки повторов и пороги оповещений, бизнес — конкретное подразделение, которое разбирает инцидент при расхождении данных.

## 4. Метрики интеграционного слоя

| Метрика | Что показывает | Где измеряется | Почему включена |
|---|---|---|---|
| Сквозная задержка | Время от события в источнике до записи в приёмнике | Все потоки с SLA в минутах: F-01, F-02, F-03, F-05, F-10 | Требование единого профиля клиента и корректного статуса платежа — это требования к задержке, а не к объёму |
| Отставание потребителя | Разница между поступившими и обработанными сообщениями | Стыки шины с MDM, с загрузкой в DWH, с CRM | Раннее обнаружение того, что MDM не справляется с пиком загрузки клиентских записей при массовом сопоставлении баз |
| Размер очереди недоставленных | Число сообщений, не обработанных после всех повторов | Входные шлюзы MDM и загрузки в DWH | Прямой индикатор поломки контракта: схема изменилась на стороне источника, а потребители об этом не знают |
| Уровень потерь сообщений | Доля сообщений, не достигших приёмника | Потоки операционных сущностей F-04, F-05 | Для финансовых данных допустимый уровень — ноль, для метаданных каталога — ненулевой |
| Пропускная способность | Число обработанных сообщений в единицу времени | Шина, каналы записи в DWH | Планирование мощностей на период массовой миграции истории RetailBank, когда поток вырастет кратно |
| Доля записей в карантине | Отношение отбракованных записей к общему потоку | Все потоки с тегом [V] | Связывает инженерный мониторинг с порогами качества из правил владения: рост доли означает, что источник изменил данные, а контракт не обновлён |
