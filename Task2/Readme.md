Проект: объединение данных FinUnion Group и RetailBank.

Задание требует показать тринадцать конкретных систем на контекстной диаграмме. Контекстный уровень по определению не раскрывает внутреннее устройство, а уровень 1 предполагает от трёх до девяти процессов, поэтому все тринадцать систем размещены на уровне 2 — с сохранением правил балансировки между уровнями. Обоснование приведено в начале `data-flows.md`.

## Ключевые решения

- **MDM берёт клиентские и справочные данные, но не учётные.** Клиент, продукт, тариф, отделение и сегмент переходят под MDM. Счета, договоры, карты, кредитные сделки, платежи и операции остаются в профильных системах: там они рождаются, там находится логика их изменения и учётная первичность.
- **Мастерство клиента разделено по атрибутам, а не передано целиком.** MDM ведёт идентифицирующие атрибуты и GCID, CRM каждого банка остаётся мастером контактных данных своих клиентов. Это разделение прямо следует из границы доменов BIAN между справочными данными стороны и управлением отношениями с клиентом.
- **Операционные сущности разделены по записям.** В переходный период каждая АБС остаётся мастером своих договоров и счетов. Двусторонняя синхронизация по правилу «последнее изменение побеждает» не применяется: она не учитывает авторитет источника и молча теряет корректные изменения.
- **DWH не является мастером ни для одной операционной сущности.** В CRUD-матрице у него нет ни одного права на создание или изменение — только чтение и агрегация.
- **Согласие выносится в отдельный контур.** Выделенного домена согласий в референсной модели нет, поэтому целевое решение выходит за её границы. В переходный период мастером остаётся CRM, выдавшая согласие, а отзыв публикуется всем потребителям с подтверждением применения.
- **Псевдонимизация вынесена в отдельный процесс на входе в аналитический контур,** а ключ соответствия — в отдельное хранилище с собственной моделью доступа. Без этого копирование данных в DWH размножает регулируемые данные в исходном виде.
- **Каждый временный механизм переходного периода получает критерий отключения.** Маршрутизация в шине, таблицы соответствия и параллельные потоки без такого критерия остаются в архитектуре навсегда.

## Как перерендерить диаграммы

```bash
for f in diagrams/dfd-*.puml; do
  java -jar plantuml.jar -tsvg "$f"
done
python3 -c "
import cairosvg, glob, os
for s in glob.glob('diagrams/dfd-*.svg'):
    cairosvg.svg2png(url=s, write_to=os.path.splitext(s)[0] + '.png', scale=1.5)
"
```
