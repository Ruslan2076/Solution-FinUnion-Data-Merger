## Ключевые решения

- **Стратегия — инкрементальная миграция волнами с параллельным прогоном.** Big Bang исключён ограничением кейса: заменить все системы RetailBank за один шаг нельзя. Паттерны: Strangler Fig для вытеснения legacy, Anti-Corruption Layer на шине для приведения моделей двух банков.
- **Порядок этапов диктуют три зависимости.** Единый клиентский идентификатор раньше объединения любых портфелей; единая статусная модель и методика расчёта просрочки раньше сведения отчётности; реестр потребителей раньше отключения legacy.
- **Пилот выбран репрезентативным, а не удобным.** Розничные клиенты одного региона присутствия обоих банков, включая пересекающихся, с мультивалютными операциями и возвратами. Регион без пересечений проверил бы только инфраструктуру.
- **Cutover расписан для передачи мастерства клиентского профиля в MDM.** Это самая связанная сущность ландшафта: ошибка расходится по всем системам-потребителям и не вызывает технического сбоя.
- **Точка необратимости определена заранее — 72 часа после переключения.** После неё возврат маршрута не работает и заменяется отдельным планом восстановления. Решение о продолжении или откате принимается до её наступления.
- **Завершение этапа не привязано к календарной дате.** Дата задаёт ориентир, решение принимается по полноте данных, результатам сверки, готовности поддержки и подтверждению владельца.
- **Каждый временный компонент получает критерий вывода и ответственного.** Реестр соответствий, параллельный ETL и двойная отчётность без этого остаются в архитектуре на годы.
- **Data Mesh в радаре находится в Assess, а не в Adopt.** Это продолжение решения из Task 3: подход оценивается по готовности организации, а не по зрелости технологии.
- **Два риска приняты без митигации и названы прямо:** часть согласий RetailBank существует только на бумаге, и доля пересечения клиентских баз неизвестна до первого прогона сопоставления.
