# Классификация данных

## 1. Шкала

| Категория | Что относится | Что меняется для архитектуры |
|---|---|---|
| Публичные | Открытые тарифы, адреса отделений, продуктовая витрина | Размещение в менее защищённых контурах при контроле целостности |
| Внутренние | Служебные справочники, правила сегментации, статусы процессов | Ограниченный доступ, аудит, назначенный владелец |
| Конфиденциальные | Тексты обращений, коммерческие условия, аналитические агрегаты по клиентам | RBAC, маскирование в интерфейсах, шифрование, контроль выгрузок |
| Регулируемые | Персональные данные, банковская тайна, кредитная история | Отдельные правила хранения, передачи, журналирования и удаления, ограничение копий |
| Критичные секреты | Полный номер карты, CVV, ключи шифрования, токены доступа к API | Vault, ротация, минимальный доступ, запрет хранения в открытом виде |

## 3. Атрибутный уровень

Категория сущности задаёт нижнюю границу режима, но не отменяет отдельной оценки атрибутов. В объединённом ландшафте выделяются три атрибутные группы с режимом строже, чем у сущности в целом:

| Группа атрибутов | Где встречается | Режим |
|---|---|---|
| Полный номер карты, срок действия, код проверки | E-07 | Не покидает изолированный контур процессинга. В остальные системы передаётся маскированный номер и токен |
| Паспортные данные, ИНН, адрес регистрации | E-01, E-09 | Отображаются по явному действию оператора с записью в журнал, в аналитический контур не передаются |
| Свободный текст обращения и вложения | E-12 | Перед индексацией в поисковом движке проходит маскирование шаблонов номеров карт, счетов и документов |

## 4. Режим обработки для аналитического контура

Требование кейса — не создавать нагрузку на операционные системы — означает копирование данных в аналитический контур, а значит, размножение регулируемых данных. Правило для объединённого ландшафта:

- В аналитический контур передаётся псевдонимизированный клиентский ключ, а не исходные идентификаторы. Связность между операциями, обращениями и договорами сохраняется, реидентификация напрямую невозможна.
- Таблица соответствия между псевдонимом и GCID хранится в отдельном контуре с собственной моделью доступа и журналом обращений. Если ключ лежит рядом с данными и доступен тем же людям, правовой режим не снижается, а пайплайн получает лишний шаг.
- Квазиидентификаторы огрубляются: дата рождения — до года, адрес — до города, отделение — до региона. Перед публикацией витрины выполняется проверка на уникальность записей по набору квазиидентификаторов.
- Анонимизация в аналитическом контуре не применяется: она уничтожает связность, без которой невозможны ни когорты по клиентам, ни расчёт кредитного риска, ни объединение обращений с операциями.
